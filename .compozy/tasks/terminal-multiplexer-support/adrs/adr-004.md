# ADR-004: Resolve continuity at restore time with terminal-first selection and truthful snapshot persistence

## Status

Accepted

## Date

2026-06-02

## Context

The approved PRD chooses a restore-first MVP. Technical clarification chose the last active terminal as the primary landing target, rejected a new return-to-focus command for MVP, and preferred reusing the current `RestoreSnapshot` and recency fields if possible.

The codebase already stores actual UI selection in `RestoreSnapshot`, tab or session recency in `lastActivatedAt`, and terminal launch intent in `WorkspaceTab`. Restore today is metadata-only and must remain truthful: the app restores app-owned context and recreates fresh terminal surfaces rather than reattaching to live processes.

The biggest architectural risk is letting continuity semantics leak into general selection heuristics or overloading persisted snapshot state to mean something other than what the user actually selected.

## Decision

Implement continuity as a restore-only selection refinement that runs after metadata is restored and before the final restored selection is applied.

The restore selector will:

- activate only when both `focusWorkspaceEnabled` and `focusWorkspaceContinuityEnabled` are true
- prefer the most recent terminal tab in the restored selected session
- fall back to the existing selected tab or normal restore behavior when no suitable terminal tab exists
- keep `RestoreSnapshot` truthful to actual last UI selection rather than persisting a separate synthetic continuity target

No new top-level command or dedicated continuity persistence model will be added for MVP.

## Alternatives Considered

### Alternative 1: Persist a dedicated continuity target

- **Description**: Add explicit continuity-target fields to `RestoreSnapshot` or a new store so restore selection never has to derive terminal-first intent.
- **Pros**: Deterministic restore targeting, explicit future expansion path.
- **Cons**: Adds schema complexity, creates a second selection concept to explain and maintain, and risks diverging from the actual UI state users last saw.
- **Why rejected**: The user preferred reusing current snapshot state if possible, and the existing recency fields are sufficient for MVP.

### Alternative 2: Change global selection heuristics everywhere

- **Description**: Make terminal-first preference part of general store selection logic, not just restore.
- **Pros**: Fewer special restore paths, one selection policy across the app.
- **Cons**: Higher regression risk, broader behavioral change for non-restore flows, and weaker separation of concerns.
- **Why rejected**: YAGNI and the restore-first PRD both favor a smaller restore-bound change.

### Alternative 3: Restore the exact last active tab, including file tabs

- **Description**: Keep current exact-selection semantics with no terminal-first override.
- **Pros**: Closest to literal last selection, minimal new logic.
- **Cons**: Conflicts with the chosen continuity behavior and reduces the chance that opted-in users land back in the primary terminal thread they intended to resume.
- **Why rejected**: The user explicitly chose last active terminal as the primary landing target.

## Consequences

### Positive

- Keeps persistence truthful and small.
- Localizes the new behavior to the restore path, reducing regression risk.
- Aligns landing behavior to the approved technical and product direction.

### Negative

- Adds restore-path branching that must be documented and tested carefully.
- May occasionally differ from the literal last selected tab, which must be explained through cues and settings copy.

### Risks

- If restore-time selection logic is spread across multiple layers, behavior may become hard to reason about.
- If recency fields do not capture enough signal in some flows, the selector may need a follow-up persistence change.

## Implementation Notes

- Add one pure restore-target selector in Core rather than modifying general selection heuristics.
- Invoke it from the restore pipeline after restored sessions and tabs exist, but before final selection is committed.
- Reuse existing search, sidebar, and session-row correction surfaces instead of adding a new command.
- Cover the selector with unit and integration tests around restore truthfulness and Focus Workspace combinations.
