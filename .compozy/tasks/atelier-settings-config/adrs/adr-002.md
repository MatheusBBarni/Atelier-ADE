# ADR-002: Curated Portable Core Product Approach

## Status

Accepted

## Date

2026-06-02

## Context

Atelier needs a product approach for turning its existing settings surface into a file-backed capability. Research and prior idea work established that users expect portable, inspectable settings in modern developer tools, but they also expect a clear boundary between personal configuration and broader project or team policy.

During PRD brainstorming, the user emphasized cross-machine portability for multi-machine power users, broad value across the main settings categories, a power-user positioning rather than a mainstream default experience, and a V1 rule that unreliable cross-machine settings should be excluded rather than forced into scope.

The product decision was whether to position V1 as a curated portability feature, a near-complete mirror of all settings, or a narrower migration-and-restore feature.

## Decision

The PRD will use the **Curated Portable Core** approach.

V1 will be framed as a power-user capability that gives multi-machine users a personal-global Atelier settings file for portable, reusable setup across machines. The product will aim for broad category coverage across the main settings areas, but only for settings that travel reliably and preserve the core portability promise.

The PRD will emphasize:

- cross-machine reuse as the primary user outcome
- a clear personal-global scope
- selective inclusion based on portability reliability
- a user-visible bridge between normal settings usage and power-user configuration workflows

## Alternatives Considered

### Alternative 1: Full Settings Mirror

- **Description**: Position V1 as a file-backed mirror of almost all settings in the current modal.
- **Pros**: Strong completeness story; easy to explain; closely matches the visible settings surface.
- **Cons**: Weakens the portability promise if some settings do not travel cleanly; creates more caveats and support burden; risks confusing users about what is truly reusable across machines.
- **Why rejected**: The user prioritized reliable cross-machine portability over exhaustive first-release coverage.

### Alternative 2: Transfer-First Setup Portability

- **Description**: Focus V1 mainly on backup, restore, and migration moments, with a lighter ongoing configuration story.
- **Pros**: Clean product narrative around setup transfer; easier onboarding story; lower expectation of regular manual editing.
- **Cons**: Underserves users who want Atelier to become part of their ongoing personal tooling setup; weaker differentiation for versioned personalization and dotfile workflows.
- **Why rejected**: The user wants the feature to support everyday reusable setup, not only migration moments.

## Consequences

### Positive

- Keeps the product promise sharp: reusable personal setup across machines.
- Supports the strongest user segment identified in research and clarification.
- Preserves room for broad value without turning V1 into an unreliable “everything settings” export.
- Aligns with how comparable tools usually phase file-backed configuration.

### Negative

- Some users may still expect full settings parity in the first release.
- The power-user positioning may limit early reach with casual users.
- The product will need to explain why some settings are included and others are not.

### Risks

- **Perceived incompleteness** — mitigate by clearly positioning V1 around portability reliability rather than universal coverage.
- **User confusion about supported scope** — mitigate through explicit product language around what travels across machines and what does not.
- **Scope pressure during delivery** — mitigate by using portability as the governing decision rule for feature inclusion.

## Implementation Notes

This ADR is a product-scope decision. The follow-on PRD should describe the capability as a power-user personalization feature connected to the existing settings experience, without expanding into project, team, or migration-only positioning.
