# ADR-004: Remove SwiftTerm after Ghostty covers the MVP terminal baseline

## Status

Accepted

## Date

2026-06-02

## Context

Atelier currently declares `SwiftTerm` in `Package.swift`, imports it in `TerminalHostController`, and uses `LocalProcessTerminalView` through `TerminalSessionDriver`. The PRD states that Ghostty should be the default terminal experience for terminal tabs and that the MVP should not expose a terminal-engine preference.

Keeping SwiftTerm in production after the migration would create a second terminal runtime to maintain and could obscure whether Ghostty actually satisfies the correctness baseline.

## Decision

SwiftTerm will be removed from production dependencies once Ghostty-backed surfaces cover the MVP baseline for current terminal behavior. The migration should remove `SwiftTerm` from `Package.swift` and delete or replace SwiftTerm-specific code and tests.

## Alternatives Considered

### Alternative 1: Keep SwiftTerm temporarily as test-only or fallback infrastructure

- **Description**: Retain SwiftTerm while Ghostty matures, but keep it out of user-facing selection.
- **Pros**: Easier fallback during implementation.
- **Cons**: Leaves ambiguous runtime behavior and prolongs dependency maintenance.
- **Why rejected**: The accepted product direction is to use Ghostty as Atelier's terminal.

### Alternative 2: Keep SwiftTerm in production as an emergency fallback

- **Description**: Route failed Ghostty terminal creation to SwiftTerm without exposing a preference.
- **Pros**: May reduce immediate terminal availability failures.
- **Cons**: Violates the no-engine-choice MVP, hides failures, and undermines correctness validation.
- **Why rejected**: Silent fallback would make it impossible to know whether Ghostty meets the baseline.

## Consequences

### Positive

- Reduces production dependency surface.
- Prevents hidden split behavior between terminal runtimes.
- Makes Ghostty correctness failures visible and actionable.

### Negative

- The migration cannot rely on SwiftTerm to mask incomplete Ghostty behavior.
- Tests that currently exercise `LocalProcessTerminalView` need replacement.

### Risks

- Removing SwiftTerm too early could block local development if Ghostty surface hosting is incomplete.
- Some launch-command tests currently tied to SwiftTerm may need a new non-UI seam.

## Implementation Notes

- Move reusable launch-command construction out of SwiftTerm-specific code before deleting `TerminalSessionDriver`.
- Keep focused unit coverage for launch metadata translation.
- Delete SwiftTerm dependency only after Ghostty host tests and manual baseline checks are in place.
