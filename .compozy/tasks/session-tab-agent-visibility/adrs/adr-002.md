# ADR-002: Adopt a focused inline navigator approach for the PRD

## Status

Accepted

## Date

2026-05-31

## Context

The approved idea established Session Tab Agent Visibility as an attention-routing feature for solo power users managing multiple local coding-agent sessions. PRD brainstorming refined the desired product behavior further.

Research showed that competing products increasingly provide glanceable agent or session management surfaces, but that users still prefer monitored and predictable workflows over fully autonomous multi-agent systems. The codebase already supports session, tab, restore, and per-tab identity concepts, but current runtime truth is limited. Atelier can confidently expose identity, restore context, recency, and exit-related signals, but it cannot yet support strong live-state claims such as active, idle, blocked, or stale with enough trust.

During clarification, the user chose a product direction optimized for faster attention routing, terminal tabs only, strictly factual status, collapsed sessions on restore, and direct jump-to-tab behavior.

## Decision

Adopt the **Focused Inline Navigator** approach for the PRD.

The PRD will define V1 as:

- an inline visibility feature inside expanded session rows
- scoped to terminal tabs only
- using agent identity plus strictly factual status signals
- preserving a calm restored workspace by keeping sessions collapsed on return
- optimizing for fast jump to the correct tab rather than broader summary or prioritization logic

## Alternatives Considered

### Alternative 1: Resume-Oriented Session Summary

- **Description**: Bias the feature toward restored-context understanding by emphasizing recent changes and passive summary signals before direct action.
- **Pros**: Stronger re-entry story, better passive understanding of what changed while away.
- **Cons**: Less aligned with the primary promise of opening the right tab fast; risks surfacing more passive information than action-oriented value.
- **Why rejected**: The user prioritized faster attention routing over resume-first behavior.

### Alternative 2: Priority-First Attention View

- **Description**: Show only the tabs or sessions most likely to matter now through more opinionated prioritization or ranking.
- **Pros**: Could reduce scan time further and feel more differentiated.
- **Cons**: Depends on more interpretive product logic and creates a higher trust risk if prioritization is wrong.
- **Why rejected**: The current product and runtime posture favors factual clarity over stronger inferred urgency.

## Consequences

### Positive

- Keeps the PRD tightly aligned with the user’s chosen outcome: faster attention routing.
- Preserves trust by constraining V1 to factual signals the product can defend.
- Supports a focused MVP with clearer scope boundaries and stronger YAGNI discipline.
- Makes direct tab selection the core interaction, which is easy to validate against success metrics.

### Negative

- The PRD will underplay richer resume behavior in the first phase.
- Users seeking stronger prioritization or broader agent monitoring will not see those benefits in V1.
- Collapsed restore behavior may reduce immediate visibility unless users intentionally expand sessions.

### Risks

- The feature may feel too subtle if the inline rows do not clearly outperform existing tab switching.
- Strictly factual status may feel less expressive than competitor surfaces.
- A terminal-only scope may leave some users wanting related file context earlier than planned.

## Implementation Notes

- The PRD should keep terminal-only inline visibility explicit.
- The PRD should avoid promising inferred live-state semantics.
- Direct selection of the correct tab should be the primary user action in success criteria and user stories.
